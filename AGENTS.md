# Engineering directives

- Treat reported defects as potential instances of a broader defect pattern.
- Investigate equivalent implementations, neighboring code and related modules before declaring a defect resolved.
- Correct the underlying cause, not merely the reported symptom.
- Apply equivalent corrections within the authorized scope when justified.
- Report related defects outside the authorized scope instead of silently modifying them.
- Preserve all established architectural decisions, security constraints and project conventions.
- Do not silently relax acceptance criteria to make tests pass.
- Re-read project instructions after context compression or session recovery.
- Before declaring completion, verify the implementation against the original requirements and persistent guardrails.
- Distinguish verified facts from assumptions.
